# Запрос админу на предоставление согласия (Admin Consent)

## Краткая версия (скопируйте и отправьте админу)

```
Здравствуйте!

Прошу предоставить admin consent для приложения "GCal to Lotus Sync" 
для синхронизации моего личного календаря Teams.

Application ID: <ваш Client ID>

Инструкция для администратора:
1. Зайти в Azure Portal: https://portal.azure.com
2. Azure Active Directory → Enterprise Applications
3. Найти "GCal to Lotus Sync" (или вставить Application ID в поиск)
4. Permissions → Grant admin consent for <your organization>
5. Подтвердить

Приложение запрашивает минимальные права:
- Calendars.ReadWrite (Delegated) - доступ к календарю пользователя
- User.Read (Delegated) - базовая информация о пользователе

Это DELEGATED permissions - доступ только к календарю авторизованного пользователя,
НЕ ко всем календарям организации.

Спасибо!
```

---

## Детальная инструкция для администратора

### Что нужно сделать

**Цель:** Разрешить пользователям организации использовать приложение "GCal to Lotus Sync" 
для синхронизации их личных календарей Teams с другими системами.

### Шаг 1: Найти приложение

1. Открыть **Azure Portal**: https://portal.azure.com
2. Перейти в **Azure Active Directory**
3. В левом меню выбрать **Enterprise Applications**
4. В поиске ввести "GCal to Lotus Sync" или Application ID: `<ваш Client ID>`

### Шаг 2: Предоставить согласие

1. Открыть найденное приложение
2. В левом меню выбрать **Permissions**
3. Нажать кнопку **Grant admin consent for [ваша организация]**
4. В диалоговом окне подтвердить:
   - ✅ Calendars.ReadWrite (Delegated)
   - ✅ User.Read (Delegated)
5. Нажать **Accept**

### Шаг 3: Проверка

После предоставления consent:
- Статус изменится на "Granted for [организация]"
- Пользователи смогут авторизоваться без запроса админа

## Что это за приложение?

**GCal to Lotus Sync** - инструмент для синхронизации календарей между:
- Google Calendar
- Lotus Notes/Domino
- Microsoft Teams Calendar

### Безопасность

**Тип разрешений:** Delegated (делегированные)
- ✅ Доступ ТОЛЬКО к календарю авторизованного пользователя
- ❌ НЕТ доступа к календарям других пользователей
- ❌ НЕТ доступа к глобальным ресурсам организации

**Запрашиваемые разрешения:**

1. **Calendars.ReadWrite (Delegated)**
   - Чтение и запись событий в календарь пользователя
   - Используется для синхронизации событий

2. **User.Read (Delegated)**
   - Базовая информация о пользователе (имя, email)
   - Используется для идентификации

### Отличие от Application Permissions

| Тип | Доступ | Риск | Admin Consent |
|-----|--------|------|---------------|
| **Delegated** (наш случай) | Только календарь конкретного пользователя | Низкий | Один раз для всей организации |
| Application | ВСЕ календари организации | Высокий | Обычно не разрешается |

## FAQ для администратора

### Вопрос 1: Это безопасно?
**Да.** Приложение использует Delegated permissions - каждый пользователь дает доступ только к своему календарю.

### Вопрос 2: Будет ли доступ к другим данным?
**Нет.** Только к календарю и базовой информации (имя, email) авторизованного пользователя.

### Вопрос 3: Сколько пользователей смогут использовать?
**Все пользователи вашей организации.** После admin consent любой сотрудник сможет авторизоваться.

### Вопрос 4: Можно ли отозвать доступ?
**Да.** В любой момент в Enterprise Applications → Permissions → Revoke consent.

### Вопрос 5: Где хранятся данные?
**Локально у каждого пользователя.** Приложение запускается на компьютере пользователя (localhost:8000), 
токены хранятся в файле teams_token.pickle на его компьютере.

### Вопрос 6: Это приложение из Microsoft Store?
**Нет.** Это внутреннее приложение, зарегистрированное в вашем Azure AD tenant (ваша организация).

## Альтернативный вариант (если админ отказывает)

Если администратор не может/не хочет давать admin consent:

1. **Попросите зарегистрировать приложение С admin consent:**
   - Azure AD → App registrations → New registration
   - После создания сразу Grant admin consent
   - Передать вам Client ID и Secret

2. **Используйте личный Microsoft аккаунт:**
   - Зарегистрируйте приложение под личным аккаунтом (Outlook.com/Hotmail)
   - Синхронизируйте с личным Teams календарем (если есть)
   - Admin consent не требуется

## Что изменится после admin consent?

**До:**
```
Пользователь → Авторизация → "Требуется утверждение администратора" → БЛОКИРОВКА
```

**После:**
```
Пользователь → Авторизация → Вход под своей учеткой → Разрешить → Успех
```

Каждый пользователь все еще должен:
1. Авторизоваться под своей учеткой
2. Разрешить доступ к своему календарю

Но НЕ будет видеть сообщение "Требуется утверждение администратора".
