# Двойники по времени и отказ от копирования

Это дополнение к ADR 0001. Одна и та же встреча может жить в двух системах под разными названиями: например, своя встреча в Lotus и чужая в Teams с другим названием, которую нельзя переименовать. Совпадение названия и начала её не находит, синхронизатор копирует каждую в обе стороны, и в календарях появляются дубли. Поэтому вопрос «это одна встреча?» теперь задаётся и тогда, когда у двух оригиналов в разных системах совпадают начало и конец, а названия разные. По умолчанию галочка у такого вопроса снята. Если пользователь отвечает «да», оригиналы становятся двойниками, и лишние копии удаляются по общему правилу.

Снятая галочка у обычного создания копии теперь означает «не копировать». Ручное применение запоминает её как отказ для этого оригинала и этой системы. Фоновая синхронизация отказов не создаёт: она выполняет только отмеченное по умолчанию. Отказ можно отменить в предпросмотре. Раньше снятая галочка значила «не сейчас», и следующий запуск, в том числе фоновый, создавал копию.

## Considered Options

- **Автоматически склеивать по началу и концу.** Отклонено по той же причине, что и склейка по названию в ADR 0001: в одно время бывают разные встречи.
- **Галочка вопроса по времени отмечена по умолчанию, как у вопроса по названию.** Отклонено: совпадение только по времени — слабый признак, и тогда фоновый запуск ошибочно связывал бы разные встречи.
- **Оставить «не сейчас» и предлагать выключить маршрут целиком.** Отклонено: пользователю нужно не копировать отдельные встречи, а не весь маршрут.

## Consequences

- Фоновую синхронизацию на новой установке нельзя включать до первого ручного применения, иначе она скопирует то, от чего пользователь ещё не успел отказаться. Первый фоновый запуск идёт через интервал, а не сразу.
- Для серии отказ запоминается для каждого экземпляра отдельно.
